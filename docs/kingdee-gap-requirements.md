## 2. 结论：金蝶的痛点里，本系统已经解决或天然满足的 4 项

1. **图片被压缩导致模糊（#2）**：本系统文件服务直存原图（`infra_file_config` → 本地 `run/uploads`），不做压缩。
2. **付款截图靠人工确认到账（#17）**：本系统已有收款凭证核验（确认 / 部分确认 / 驳回 → 自动转"待发货"）。
3. **复制订单沿用调整前价格（#17）**：H5「再来一单」已按当前商品数据重取价格与库存，失效行项自动跳过。
4. **商品搜索必须输对全名（#16 部分）**：`ProductSpuMapper` 用的是 `name LIKE` 包含匹配（可增强条码/别名/拼音容错）。

## 4. 必须先决策的口径冲突（4 项，影响设计）

1. **「仓库自提 / 末端自提」（#17）与已下线的门店自提冲突**：按你此前要求，"门店自提"已整体下线
   （`DeliveryTypeEnum` 只保留快递、自提点表已物理删除）。需求里的"特殊需求（仓库自提/发货拉拉/末端自提）"
   是否要重新引入？如果要，建议做成**订单特殊需求标签**（不影响配送方式枚举），而不是恢复自提点体系。
2. **余款（#20/#22）不能用钱包**：钱包/充值已按"全线线下转账"归档。余款应实现为**预收款余额台账**
   （门店线下多付/折算/抵扣的明细），语义是"预收款"，不是"线上钱包余额"。
3. **多品牌入口（#16/#18）是租户还是品牌**：系统目前只有 2 个租户（亚特 / 亚特餐饮），而业务上有
   卤校长、萍姐(PT)、萍姐(一企创)、杨老头、耙二哥、直营等"组织"。需要确认：多品牌 = 多租户（数据隔离）
   还是同租户下的品牌维度（组织树分组）？这决定统一登录账号如何"自动下推到相应组织"。
4. **代理商层缺失**："一个代理同时有卤校长、萍姐等门店"意味着组织模型需要**代理商/客户 → 多门店**
   的层级（当前只有门店节点 + 单个 `erp_customer`），H5 需要"门店切换器"。已补入 `organization-model.md`。

此外两项依赖外部条件：**付款截图关键词识别（#16）** 需要 OCR 能力（当前 DeepSeek key 只有文本模型，
无视觉），可先用"必须上传、可人工核验"的现有流程兜底；**美团门店映射与订营比（#22）** 需要美团开放平台
接口资料与商户号。
