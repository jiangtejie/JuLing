# 亚特供应链业务系统重构方案 V1（智能版）

> 编制输入：①《重庆亚特餐饮业务蓝图V3.0》（金蝶，2023-06-19，含 19 个流程与主数据口径）；
> ②《CY-001 重庆亚特餐饮整体业务流程》泳道图与集团组织架构图；③《金蝶业财功能意见收集表_供应链2026.9.21》
> （23 条一线痛点）；④ 本仓库现状实测与已完成的门店订货链 S1。
>
> 结论先行：**系统定位不是"再做一套金蝶"，而是用一套自研系统替代「美团供应链 + 金蝶业财」这两段**，
> 先做扎实**供应链进销存 + 门店订配**，单据体系按"将来直接接财务"的标准设计。
> 分期路线见第 12 节；本次交付的是**方案**，不含实施。

## 2. 系统定位与边界

| 现在是谁在干 | 内容 | 本系统怎么办 |
|---|---|---|
| 美团 | 门店前端收银 + 供应链（订货/配送）| **替代**：订货（H5/PC）+ 订配 + 门店收货 + 门店库存 |
| 金蝶 | 财务、费用报销、业财一体化 | **分两步**：先替代其**业务侧**（采购/存货/应收应付单据），后期替代**核算侧**（凭证/报表）|
| 飞书 | 客诉流转、审批沟通 | **替代**：系统内客诉单 + BPM 审批 + 待办 |
| 微信 | 通知 | **替代**：站内信 + 待办中心 |

三条业务特点决定了架构取向：**多品牌**（订配与库存可见性按品牌隔离）、**直营/加盟并存**（管控强度不同）、
**业财分离→业财一体**（业务单据必须先规范，财务才可能自动化）。

## 4. 单据体系设计（核心）

用户要求"该有的单据应该得有，方便后期做财务板块"。做法是**先定单据族与统一基座，再逐张实现**，
而不是每张单据各写一套增删改查。

### 4.1 统一单据基座（头/行/状态/审批/日志/关联/附件）

所有业务单据共有的能力，抽成基座，单据只声明差异：

| 基座能力 | 内容 | 现状 |
|---|---|---|
| 头/行结构 | 单据头（组织/品牌/仓库/往来单位/日期/经办人/金额）+ 行（物料/SKU/单位/数量/单价/金额/税/批次/效期/仓库）| 各表独立，字段命名不一 |
| 状态机 | 草稿 → 已提交 → 审批中 → 已审核 → 执行中 → 已完成 / 已作废；**反审核**受控 | ERP 仅有"未审核/已审核"两态；订单另有 5 态 |
| 审批 | BPM 流程定义按单据类型 + 金额/组织/店型路由 | 仅门店要货已接 |
| 留痕 | 操作日志、字段级变更、审批意见、附件 | 部分有 |
| 关联关系 | 上溯下推（订单→入库→应付；要货→出库→收货；退货→红字）+ 防重复下推 | 有部分字段（biz_id/biz_no），无统一模型 |
| 编号 | 单据类型 + 组织/品牌 + 年月 + 流水，可按组织重置 | 有 TradeNoRedisDAO / ERP 各自实现 |
| 扩展字段 | 单据扩展表（key-value + 类型），避免为小需求改表 | 无 |

> 这一层是"长期稳定维护、方便扩展"的地基：后续新增单据（如门店自采单、跨组织调拨）应只写业务规则。

## 5. 主数据（长期维护的第一性问题）

蓝图明确"物料是业务系统最基本的基础资料，含基本信息/采购/库存/销售四类属性"，并建议**设专岗维护**。
据此确立三条原则：**一处建档、多域引用**；**主数据不带业务流水**；**所有单据只存 id + 必要快照**。

| 主数据 | 目标模型 | 现状差距 |
|---|---|---|
| 物料 / SKU | **物料(SPU) + SKU 两级**：物料管采购与库存属性，SKU 管规格/条码/单位换算；蓝图口径的"编码/名称/规格/助记码/物料属性/存货类别/允许采购"落到物料字段 | ERP 产品无 SKU；商城 SPU+SKU 是另一套，两套并存（**重构重点**）|
| 计量单位 | 单位 + 换算率（多单位：采购单位/库存单位/门店订货单位）| ERP 有单位表但无换算矩阵 |
| 门店 / 客户 | 门店 = 客户档案 + 组织（部门）节点 + 订货账号（一店三面，S1 已建）；店型（直营/加盟）、结算模式、账期、信用额度、所属品牌/代理 | S1 已建字段，**真实门店待建档（G9）** |
| 供应商 | 名称 + 开票资质 + 结算方式/账期 + 多账户 + 合同×组织 + 交期 + 寻源（可供品类）| 设计完成待实施 |
| 价格中心 | 采购价历史（只追加） + 配送价版本（生效日期） + 价格政策（客户/等级/阶梯）| 设计与实施均未完成；现存两套价互不同步 |
| 仓库 / 货位 | 中心库、门店虚拟仓、三方仓、在途仓；仓库归属组织与品牌 | 仅 1 个仓库；无货位、无门店仓 |
| 组织 / 品牌 | 部门树 = 组织；品牌 = 部门分支（萍姐/卤校长/直营门店/中心库）；注销组织保留 | 组织树已归位；**品牌维度尚未进单据** |
| 会计主数据（预留）| 科目、辅助核算、结算方式、税率、费用项目 | FMS 已有科目/账套/辅助核算，ERP 单据未对接 |

## 6. 库存与成本（进销存的"存"）

| 设计点 | 方案 | 现状差距 |
|---|---|---|
| 库存维度 | 仓库 × SKU × 批次 ×（效期）记账；门店仓与中心库同构 | erp_stock 只有 productId/warehouseId/count |
| 状态口径 | **在仓 / 在途 / 占用 / 待检** 四态；可用量 = 在仓 − 占用 + 在途 | 只有在仓 |
| 库存流水 | 一张流水表贯穿所有单据（入/出/调/盘），单据可反查流水 | 有 erp_stock_record，字段偏薄、未覆盖新单据 |
| 成本策略 | **蓝图口径：启用总仓核算 + 计价方法＝先进先出法（FIFO）**；但蓝图同时写明**批号管理不启用** —— 无批次维度下的"先进先出"缺少发出顺序依据，二者冲突，**必须业务复核**（见 §14-1）。系统实现为策略模式，默认 FIFO + 入库时间序，可切加权平均 | 完全无成本字段 |
| 成本分步 | 蓝图核算顺序：**材料出库核算 → 加工自制品核算 → 食品成本核算**；其他出入库单需人工录入金额（无来源价）| 无 |
| 期末 | **先仓存关账（当期单据禁增改）→ 生成凭证 → 财务结账**；应付侧支持反结账 | 无 |
| 期末处理 | 期末结存、成本重算、期间锁定（与 FMS 结账联动）| 无 |
| 三方仓 | 复用 WMS 模块（13 张表全空）对接三方仓批次与库存 | 未启用 |

## 7. 订货与订配链（"进销存 + 订货"的订货）

S1 已完成：一店三面绑定、代理商多门店切换、订单归属快照、**加盟审核 / 直营免审**分流、发货闸门。
后续按蓝图补齐（对应 CY-002~CY-010）：

0. **三种订货入口**（蓝图明确，L600-L622）：**订货模板**（按门店维护可下单物料，蓝图有、我们缺）、
   **历销复购**（按历史要货单再来一单，我们的"再来一单"已实现）、**手工选购**（搜索加入订货单，已有）。
1. **订单工作台**（S4 核心）：汇总待处理要货 → 分料判定 → 改量/拆行 → 指定收货仓 → 下推。蓝图分支：
   **统配**（门店要货申请单 → 配送出库单 → 门店收货单 → 门店应付单；配送出库单 → 中心库应收单）或
   **直拨**（要货申请单 → 采购订单 → 门店采购入库单 → 应付单，**同时形成一张内部配送出库单，执行系统＝N**）。
   **自采**（CY-007）：要货申请单 → 门店采购订单 → 门店采购入库单 → 应付单，供应商直对门店。
2. **收货与差异**（CY-003/004）：门店收货单支持多收/少收，生成**配送异常通知单** → 异常处理选"配送补货" →
   **配送补货单**；同时仍按收货单出应付、按配送出库单出应收。**注意：蓝图把多收与少收写成同一套动作，
   且未定义差异对结算金额/成本的影响**（见 §14-2）。
3. **退货**（CY-005）**必须"有源单"**：门店收货单 → 门店退货申请单 → 配送退货单（退回中心库）→ 中心库按物料
   可用性生成**报损出库单**；蓝图未给退货的应收/应付冲减口径（见 §14-2）。
2. **收货与差异**（CY-003/004）：门店收货单支持**多收/少收**，差异生成差异单并驱动对账与成本调整
   （蓝图对多收/少收有明确处理规则，按子代理提炼的口径落地）。
3. **门店退货**（CY-005）、**门店调拨**（CY-008）、**门店盘点**（CY-009）、**门店报损**（CY-010）。
4. **门店自采**（CY-007）：门店采购订单/入库/退货，应付归属门店（影响后期费用与报销）。
5. **门店库存**（G4）：门店维度的收/发/存账与"门店成本核算"（CY-011）——这是"强管控门店库存与食品成本"的抓手。
6. **订货端**：H5 已有；补 PC 订货端与导出、物流时效表、地图地址、付款截图校验。

## 8. 财务衔接（本期只建地基，不建总账）

做法是**业务与会计解耦**：业务单据不写分录，只发**会计事件**；由**凭证规则**把事件映射成凭证，交 FMS 记账。

| 环节 | 设计 | 依据 |
|---|---|---|
| 会计事件 | 事件表：事件类型（采购入库/销售出库/收付款/盘盈亏/报损/费用）+ 单据引用 + 金额 + 税额 + 组织 + 科目建议 | 为 CY-015/016 预留 |
| 凭证规则 | 规则表：事件类型 → 借贷模板（科目由物料"存货类别"、结算方式、税率驱动）| 蓝图主数据里"存货类别对应不同存货科目" |
| 应收应付 | 应收：门店配送出库 → 应收 + 账期；应付：采购入库 → 应付 + 账期（含直拨）| CY-016 |
| 对账开票 | 客户/供应商对账单、发票登记（本期只登记不验真）| 一线需求 |
| 跨组织结算 | 中心库与门店所属组织间的内部结算（CY-014）| 需组织/品牌维度进单据 |
| 总账 | 复用 FMS（科目 94/账套 1/辅助核算 7/凭证模板齐备），缺的是"业务单据自动生成凭证" | 蓝图 FMS 模块已在库 |

## 10. 技术架构与工程规范

- **模块边界**：新增 erp-api（已建）、后续 fms-api、wms-api；跨模块只走 api；禁止跨模块直连表。
- **单据基座**：抽象单据统计头/行/状态/审批/日志/关联/扩展字段，以模板方法收敛，避免 N 套 CRUD。
- **事件驱动**：单据状态变更发事件（Spring 事件 + MQ 可选），下游订阅（库存、成本、会计事件、待办）。
- **幂等与一致性**：所有下推接口幂等（业务键去重），关键链路本地事务 + 事件表补偿；对账任务每日跑库存/往来。
- **扩展性**：字典驱动枚举、规则表驱动审批与预警、单据扩展字段表承接小需求，不改表即可上线。
- **可观测性**：单据全链路 trace（单据号贯穿日志），异常落库 + 告警。
- **数据迁移与双跑**：期初库存/往来/在途单导入 → 与美团/金蝶并行一个完整账期，每日对账（库存、应收、应付）。
- **权限**：菜单权限 + 数据权限（按组织/品牌/门店）+ 字段权限（成本价、毛利对业务员不可见）。

## 11. 该重构的重构 / 该保留的保留

**重构（地基性，越早越省）**
1. **商品主数据统一**（物料+SKU 两级，ERP 与商城一套）—— 否则库存与成本永远算不准；
2. **库存中心重做**（多状态 + 批次 + 成本 + 流水统一）—— 现有 erp_stock 无法承载蓝图口径；
3. **单据基座与单据链自动化**（采购订单审核自动生成入库、要货下推出库）—— 现在是人工推单；
4. **价格中心**（采购价历史 + 配送价版本 + 取价规则）—— 现在两套价互不同步；
5. **组织/品牌维度进单据**（单据带组织、品牌、仓库、门店）；
6. **会计事件与凭证规则**（业务不做分录，规则生成凭证）；
7. **审批覆盖面**（BPM 扩展到采购、付款、调价、自采）。

**保留 / 复用**
- 交易订单与线下收款核验（已上线且验证充分）；
- FMS 总账、BPM、消息待办、权限/组织、文件服务、AI 模块骨架；
- MES 的质检能力（采购到货质检可直接复用，不必新建）；
- WMS 模块（作三方仓对接落点）。

## 13. 风险与待确认

**风险**：① 主数据统一牵动商城与 ERP 两侧，切换窗口要选在业务低峰并做双跑；
② 成本口径一旦定错，历史数据要重算，故 S2 必须先定计价方法与运费/税额归属；
③ 组织/品牌维度进单据需回填历史数据；④ 美团收银数据若拿不到，门店成本与智能补货会缺一环。

**待确认（按优先级）**
1. 存货计价方法（移动加权 / 月末一次加权 / 批次）与成本构成（是否含运费、税）；
2. 加盟店审核是**财务单级**还是财务 + 供应链两级（影响 S1 收尾与工作台设计）；
3. 门店自采是否纳入本期（涉及应付归属与报销）；
4. 直拨的入库仓记门店还是中心库（影响库存与成本归属）；
5. 美团营业数据的获取方式（接口/导出）与门店主数据编码映射；
6. 是否保留"注销组织"参与历史数据归属（蓝图要求初始化时加入）；
7. **计价方法与批次管理二选一**（蓝图自相矛盾，见 §14-1）——这条直接决定库存中心与成本模型，是 S2 的开工前提；
8. 直拨的采购与应付主体是总部还是门店（蓝图自相矛盾，见 §14-3）；
9. 300+ 加盟店的主数据与订货账号是否需要批量导入工具（现有 13 家是样本规模）；
10. 食品成本卡与替代方案是否纳入本期（依赖配方/用量维护，但它是门店食品成本管控的核心模型）。

## 14. 金蝶蓝图 V3.0 精读回填（权威口径 / 冲突 / 缺口）

> 本节是子代理逐行精读《业务蓝图V3.0》（1281 行解析文本）后的结论，**优先于前文相应描述**；
> 括号内 L 编号为解析文本行号，便于回查。

### 14.1 蓝图给我们的权威口径（照做）

1. **物料 7 个业务开关**：允许采购 / 销售 / 库存 / 生产 / 委外 / **统配 / 直拨**（L206-L219）——
   "统配/直拨"是物料级属性，比我们"订单行级分料"更前置，两者要一起用（物料定默认，订单行可覆盖）。
2. **物料采购参数**：采购单位 / 采购计价单位 / 采购组 / 采购员 / 默认供应商 / **货源控制** / 需要请购 /
   采购批量（最小递增量）/ 最小订单数 / **收货上下限比例**（示例：订单 100、上限 5%、下限 10% ⇒ 允许收 90–105，
   L263-L278）/ 配额管理 / 配额顺序（顺序优先·固定比例·固定供应商·价格优先）/ 代理采购加成比例。
   其中**收货上下限比例**正是张新宇要的"超收少收自动标红"的规则源。
3. **多计量单位分离**：库存单位 / 辅助单位 / 采购单位 / 采购计价单位 / 销售单位 / 销售计价单位，
   且**辅助单位不得与基本单位存在固定换算**（L225-L252）——与我们"单位换算矩阵"的设计需对齐。
4. **批号管理＝不启用、全文无保质期/效期字段**（L233-L235；检索"保质期|效期|有效期"零命中）——
   与餐饮食材管理的常识不符，需业务复核（见 14-3）。
5. **取价一律由价目表驱动，且引用前必须"已审核非禁用"**：采购价目表 → 采购订单；销售价目表/折扣表 → 客户；
   **组织间结算价目表** → 内部结算；主数据上挂默认价目表；另需**货源清单**（L466-L479、L534-L537、L1118）。
6. **门店与配送中心是两个独立核算主体**：同一笔配送，**收货方生成应付、发货方生成应收**（L636-L646）。
7. **内部交易单据"不更新即时库存、但参与存货核算"**（L1122）——库存与核算必须解耦，这条决定了我们的
   单据模型要带"是否影响库存 / 是否影响核算"两个标志位。
8. **必须内置的报表口径**：存货收发存（期初/收入/发出/结存，含盘盈盘亏、本期消耗）、**入库勾稽**
   （入库类单据与关联应付单勾稽）、**异常余额**（无数量有金额 / 有数量无金额）、**账龄**（未核销完的
   应付单 / 付款单 / 付款退款单）（L1165-L1186、L1251）。
9. **企业概况（用于规模校准）**：三大品牌（耙二哥火锅、卤校长火锅、萍姐火锅×公路夜市），员工 700+，
   总部 10 大核心部门，**直营门店 11 家、加盟店 300 余家**；现用系统＝美团（收银+供应链）、金蝶（财务+报销）
   （L108-L117）。—— 加盟 300+ 说明**门店主数据与订货账号的批量建档、批量授权**是硬需求。

|---|---|---|
| 1 | **计价方法冲突**：写"总仓核算 + 先进先出法"（L1138），却**不启用批号管理**（L233）——没有批次，"先进先出"的发货顺序无依据 | 二选一：①启用批次/效期（餐饮食材更合理，也能支撑"强管控食品成本"）；②承认实际是**月末一次加权平均**。建议按①设计、按②保底，**上线前由财务拍板** |
