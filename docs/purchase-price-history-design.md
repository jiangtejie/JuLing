# 采购价格历史成本与成本异动设计（采购部门需求）

> 来源：采购部门 —— 金蝶采购价目表只能看最新成本，看不到历史；希望有历史曲线、异动分析、
> 波动预警、降本标记、成本卡录入、改价后检查配送价；退一步"至少要每次变动都有时间、原因、变动人"。
> 本文给出落地方案。相关：[`docs/supplier-master-data-design.md`](./supplier-master-data-design.md)、
> [`docs/intelligent-system-blueprint.md`](./intelligent-system-blueprint.md)。

## 1. 现状盘点（关键结论：数据源早就在库里，缺的是账本）

| 项 | 现状 | 依据 |
|---|---|---|
| 采购价明细 | **已有**：采购订单/入库/退货明细均带 `product_price` / `tax_percent` / `tax_price` / `count` / `total_price`，单据头有供应商与日期 | `ErpPurchaseOrderItemDO`、`ErpPurchaseInItemDO`、`ErpPurchaseReturnItemDO` |
| 最新成本 | 商品档案单值 `erp_product.purchase_price`（另有 sale_price / min_price） | `ErpProductDO:76` |
| 历史成本表 | **不存在**（全库无 price/cost/history/adjust 相关表） | `information_schema` 查询 |
| 调价单 | **不存在** | 同上 |
| 改价留痕 | **没有**：`ErpProductServiceImpl.updateProduct` 不写任何日志 | 源码检索 |
| 库存成本 | **没有成本字段**（`erp_stock` 仅 productId / warehouseId / count） | `ErpStockDO` |
| 图表能力 | **具备**：`@vben/plugins/echarts` 的 `EchartsUI` / `useEcharts`（mes、home 已在用） | 插件源码 |

**根因**：金蝶把采购价当成商品档案上的一个字段（覆盖写），所以只剩最新值；而本系统的采购单据明细
本就是"商品 → 供应商 → 日期 → 价格"的流水，只是从未被当作价格历史来查。所以需求 1–4 不是"能不能做"，
而是"补一张只追加的账本 + 三个视图"。

## 2. 设计主线：价格流水账本（只追加）

### 2.1 核心表 `erp_product_cost_history`

| 列 | 说明 |
|---|---|
| `product_id` / `supplier_id` | 商品与供应商（供应商可空：档案改价、标准成本无供应商） |
| `price_type` | 采购价 / 含税采购价 / 标准成本（成本卡）/ 配送价（售价快照） |
| `price` / `tax_percent` / `tax_price` | 价格与税率、含税价（沿用单据口径） |
| `effective_date` | 生效日期（取单据业务日期，非写入时间） |
| `source_type` / `source_id` / `source_no` | 来源：采购订单 / 采购入库 / 商品档案改价 / 手工调价 / 成本卡 / 期初导入，附单据号 |
| `prev_price` / `diff_amount` / `diff_percent` | 旧价、差额、涨幅（写入时算好，查询不必再聚合） |
| `change_reason` | 变动原因（单据来源自动生成，如"采购入库 CG202601xxx"；手工调价必填） |
| `creator` / `create_time` | **变动人、变动时间**（沿用 yudao 审计列，无需额外字段） |

**写入时机（四处钩子，全部只追加、不覆盖）**：
1. 采购订单审核通过（约定价）—— `ErpPurchaseOrderServiceImpl` 审核处；
2. 采购入库审核通过（实际价）—— `ErpPurchaseInServiceImpl` 现有 `stockRecordService.createStockRecord` 附近（已定位到 186 行）；
3. 商品档案改价（`ErpProductServiceImpl.updateProduct`）—— 即使不走单据也留痕；
4. 手工调价单 / 成本卡录入 —— 新页面，强制填"变动原因"。

> 这一层就是需求末尾的兜底项：**留痕不是退路，而是 1/2/3/4 的共同地基**。只要表在，即使其余
> 页面分期上线，"每次变动有时间、原因、变动人、来源单据"也立刻可查。

### 2.2 需求 1：历史成本曲线（跨年趋势）

接口：`GET /erp/product-cost/history?productId&supplierId&startDate&endDate`（明细）、
`GET /erp/product-cost/trend?productId&granularity=month|quarter|year`（按期间取均价/最低/最高/末值）。
页面：商品成本详情 —— 顶部 `EchartsUI` 折线（可叠加多个供应商对比曲线，跨年连续），下方同数据的明细表
（日期、供应商、价格、含税价、来源单据、变动原因、变动人）。支持导出。

### 2.3 需求 2：成本异动（旧价 / 新价 / 差额 / 涨幅）

相邻两条流水求差即可，无需额外表；页面"成本异动"：时间范围 + 商品/分类 + 供应商 + 只看上涨/下降 +
涨幅阈值过滤，列：商品、供应商、旧价、新价、差额、涨幅、发生日期、原因、变动人、来源单据。
附"异动汇总"：按商品、按供应商的涨幅 TOP（用于快速发现异常涨价）。

### 2.4 需求 3：价格波动预警（超过 ±x% 自动提示）

- `erp_cost_alert_rule`：适用范围（全局 / 商品分类 / 指定商品）、对比基准（上次采购价 / 近 N 次均价）、
  阈值（上涨 % / 下跌 %）、是否启用、通知对象；
- `erp_cost_alert_record`：命中记录（商品、供应商、旧新价、涨幅、时间、状态[待确认/已确认/已忽略]、
  处理人、处理备注、来源流水）；
- 触发：写流水时同步判定；展示：预警列表红标 + 顶栏角标，可选站内信（复用 `system_notify_message`）。
- 阈值支持"全局默认 + 商品级覆盖"，先默认全局（如 ±5%）。

### 2.5 需求 4：降本产品标记 `*降本产品`

新流水价格低于上一条 → 打标。**建议独立表 `erp_product_cost_tag`**（商品、标记类型[降本/涨价]、起始日期、
降幅、来源流水、结束日期），而不是商品表上加一个布尔列 —— 否则跨年就无法回答"去年有哪些降本产品"。
商品列表增加"降本"标签列与筛选，可统计某期间降本产品数与累计降本金额。

### 2.6 需求 5：成本卡录入

新表 `erp_cost_card`：商品、供应商（可空）、标准成本、生效起止、版本、状态（草稿/生效/失效）、附件、备注。
用途：与实际采购价对比算**标准成本差异（节约 / 超支）**，并作为"降本"判定的基准线。
（若"成本卡"指的是**配方/BOM 成本卡**——成品由原料组成、按用量卷积出理论成本——则数据基础是 MES 已有的
`mes_md_product_bom`，可二期做卷积。两者语义不同，需确认，见第 5 节。）

### 2.7 需求 6：采购价变化后提示检查配送价

采购价上涨（或倒挂）时，自动生成"待检查价格清单"：取该商品对应的配送价（商城 `product_sku.price` /
ERP `erp_product.sale_price`），命中条件：新采购价 ×（1 + 目标毛利率）> 配送价，或 配送价 < 采购价。
清单支持一键跳转商品/商城改价；改价动作同样写回流水（`price_type = 配送价`），形成"成本→售价"的联动闭环。
> 落地前需确认"配送价"指代：本仓库里 `deliveryPrice` 是**运费**；若指给门店的配送/供货价，
> 落点是 `product_sku.price`（商城）与 `erp_product.sale_price`（ERP）。见第 5 节。

## 3. 分期落地

| 阶段 | 内容 | 工期 |
|---|---|---|
| 一期 | `erp_product_cost_history` + 四处写入钩子 + 成本历史/曲线页 + 成本异动页（需求 1、2 与兜底留痕） | 3–4 天 |
| 二期 | 预警规则表 + 预警记录 + 列表红标/站内信（需求 3） | 2–3 天 |
| 三期 | 降本标记 + 成本卡（标准成本差异）+ 配送价检查清单（需求 4、5、6） | 2–3 天 |

一期上线后即可回答采购部门最关心的问题："这个商品历年从各供应商买过什么价、哪次涨的、谁改的、为什么"。

## 4. 与金蝶的本质差异

金蝶是**档案式**（覆盖写，只剩最新值），本设计是**流水式**（只追加，永不丢历史），且与商城/门店同库，
因此"改价提醒"能直接落到配送价与单据，不需要跨系统同步。这也顺带为蓝图二期的**存货成本核算**
（加权平均/批次）准备好了价格依据。

## 5. 待确认（影响表结构与口径）

1. **"配送价"指什么**：给门店的配送/供货价（对应 `product_sku.price` / `erp_product.sale_price`），
   还是运费（`deliveryPrice`）？决定需求 6 的比对对象。
2. **"成本卡"指什么**：标准成本（目标成本，用于算节约/超支），还是配方/BOM 成本卡（MES `mes_md_product_bom`）？
3. **价格口径**：以采购订单价（约定）还是入库价（实际，含运费/税）为准？两者不一致时建议都留痕并标记来源。
4. **预警阈值与通知方式**：全局一个阈值还是按商品/分类分别？命中后走站内信还是仅列表提示？
