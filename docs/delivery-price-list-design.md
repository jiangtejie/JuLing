# 配送价目表 · 价差毛利 · 历史售价设计（采购部门需求4）

> 来源：采购部门 —— 配送价目表板块需要：① 自动算价差/毛利（配送价 − 采购成本）与毛利率，实时掌握盈利；
> ② 毛利低于设定值自动标记；③ 历史售价可查。
> 本文给出落地方案。姊妹文档：[`docs/purchase-price-history-design.md`](./purchase-price-history-design.md)
> （采购成本账本，本文的成本来源）、[`docs/organization-model.md`](./organization-model.md)（门店/客户主体）。

## 1. 现状盘点（两套价、零毛利视图）

| 位置 | 字段 | 实测数据 |
|---|---|---|
| 商城（H5 门店看到的价格）| `product_spu.price / market_price / cost_price`、`product_sku.price / market_price / cost_price`（整数、单位**分**）| 16 个 SPU/SKU（测试数据"土豆"）：price 400（¥4.00）、market 500、cost 100（¥1.00）|
| ERP | `erp_product.purchase_price / sale_price / min_price` | 2 条：土豆（进 1.00 / 销 2.00 / 最低 1.50）、红烧猪蹄（进 335.10 / 销 498.00 / 最低 空）|
| 历史售价 | **不存在** | 全库无 price/cost/history 表 |
| 毛利视图 | **不存在** | 没有任何毛利/价差计算 |
| 商城 sku 的 `cost_price` | 有字段但**未与采购价打通**（手工填的 100）| 不会随采购价变化 |

结论：**"配送价"目前事实上就是商城的 `product_sku.price`**（门店在 H5 下单看到并支付的价格），
企业侧的对应值是 `erp_product.sale_price`；两者并存且互不同步（正是蓝图 4.1 商品主数据未统一的表现）。
成本侧则刚在姊妹文档里建了"只追加的采购价格账本"，本文的毛利全部以它为成本来源。

## 2. 设计

### 2.1 配送价目表主表 `erp_delivery_price`（只追加版本，不覆盖）

| 列 | 说明 |
|---|---|
| `product_id` / `sku_id` | 商品；主数据统一后按 SKU（现阶段 SKU 可空，商品级即可） |
| `delivery_price` / `tax_percent` / `tax_price` | 配送价（不含税 / 税率 / 含税），口径与采购账本一致，便于直接算价差 |
| `scope_type` / `scope_id` | 适用范围：全局 / 客户等级 / 指定客户 / 指定门店。**一期只做全局**，但列先留好，二期做门店差异化价不用改表 |
| `effective_date` / `expire_date` | 生效与失效日期（版本化：新价新增一条并把上一条的失效日期补齐，**永不覆盖**）|
| `status` / `source_type` / `source_id` | 状态（草稿/生效/失效）、来源（手工录入 / 调价单 / 采购价联动建议 / 期初导入）|
| `change_reason` | 变动原因（配合"采购价变化后检查配送价"的闭环，必填）|
| `creator` / `create_time` | **变动人、变动时间**（审计列，天然留痕）|

**历史售价（需求 3）= 这张表的版本流水本身**，不需要第二张历史表。查询"某商品在 2026-03-01 的配送价"
就是取 `effective_date <= d < expire_date` 的那一条；"历史毛利率"则是把历史售价与同期采购成本账本按
日期 join —— 于是需求 1 与需求 3 合成一条**历史毛利曲线**（这是金蝶给不了的：它连售价历史都不留）。

### 2.2 价差与毛利（需求 1）

计算：`价差 = 配送价 − 采购成本`；`毛利率 = 价差 / 配送价`（口径可切换为"加价率 = 价差 / 成本"）。
**成本口径可配**（默认：最新入库价）：
1. 最新入库价（与采购部门口径最贴近，默认）；
2. 近 N 次采购均价（抹平单次波动）；
3. 移动加权平均（等蓝图二期做了存货成本后切换）；
4. 标准成本卡（对接 `erp_cost_card`，算标准成本差异）。

页面（配送价目表）：列 = 商品/SKU、配送价、采购成本（含来源单据与日期）、价差、毛利率、环比变化、
状态标签（`低毛利` / `倒挂` / `降本`）；顶部汇总卡片 = 商品数、平均毛利率、低毛利数、倒挂数、本月调价数；
支持按毛利率升序排（先看最差的）、按分类/供应商/门店筛、导出。

### 2.3 毛利异常提醒（需求 2）

与采购侧的波动预警**共用一个引擎和一张记录表**，不另起一套：
- 规则表 `erp_margin_alert_rule`：适用范围（全局 / 分类 / 指定商品）、下限类型（毛利率 % / 价差金额）、
  阈值（如毛利率 < 15%）、是否启用、通知对象；
- 记录表与成本预警合并为 `erp_price_alert_record`，用 `alert_type` 区分：
  `COST_UP`（采购价涨幅超阈值）/ `MARGIN_LOW`（毛利低于阈值）/ `PRICE_INVERSION`（配送价低于成本）；
- 触发时机：配送价变更、采购价变更（写账本时）、规则变更后重算；展示：列表红标 + 状态流转
  （待处理 / 已调价 / 已确认接受 / 已忽略）+ 处理人备注；可选站内信。

### 2.4 与"采购价变化后检查配送价"的闭环

采购价上涨（`COST_UP`）→ 系统按该商品毛利重算 → 若跌破阈值则生成 `MARGIN_LOW` 并进入
**待调价清单** → 供应链/财务改配送价（写 `erp_delivery_price` 新版本 + `change_reason`）→
商城 `product_sku.price` 同步更新 → 预警记录置为"已调价"。这条路走通后，"采购成本→配送价→门店售价"
就是同一条可追溯的链条。

### 2.5 权限与管控

配送价属**价格政策**，建议：采购部可查看与申请，供应链/财务可审批与执行（可走 BPM，引擎已在库中）；
配送价变更必须填变动原因并留痕；按角色控制"是否可见成本与毛利率"（业务员只看配送价，不看成本）。

## 3. 分期落地

| 阶段 | 内容 | 工期 |
|---|---|---|
| 一期 | `erp_delivery_price`（版本化）+ 配送价目表页（价差/毛利率/汇总卡片）+ 与商城 `product_sku.price` 的单向同步 + 历史售价查询 | 3–4 天 |
| 二期 | 毛利规则 + 与成本预警合并的 `erp_price_alert_record` + 待调价清单 + 站内信 | 2 天 |
| 三期 | 门店/客户等级差异化配送价（`scope_type` 启用）+ 历史毛利曲线（售价版本 × 成本账本 join）| 2–3 天 |

## 4. 待确认

1. **配送价的权威源**：以商城 `product_sku.price` 为准（门店实际支付价），还是 ERP `erp_product.sale_price`？
   建议**配送价目表为唯一权威源、商城 ERP 都从它同步**（避免今天这种两套价互不同步）。
2. **成本口径**：默认"最新入库价"是否可接受？含税与不含税必须与配送价同口径（否则毛利率失真）。
3. **毛利率下限**：全局一个值（建议先 15%），还是按分类/商品分别设定？
4. **门店差异化**：一期是否真的只需全局统一配送价（差异化留二期）？
